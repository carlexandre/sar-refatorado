# Auditoria de saída SMTP — VM SAR

Data: 08/10/2026, horário de Brasília. Origem: 10.85.3.180 (eth0).

## Evidências

- DNS resolve smtp.gmail.com; os endereços abaixo são os retornados durante este teste e podem mudar.
- Rota IPv4 padrão: via 10.85.3.46, dev eth0. O vizinho 10.85.3.46 consta como REACHABLE.
- A VM não possui rota IPv6 padrão; esse caminho retorna errno 101 imediatamente.
- UFW: inactive, conforme saída fornecida pelo operador. Regras iptables/nftables e filtros do gateway não foram inspecionados com privilégios administrativos.
- SAR UI: ativo, health HTTP 200. Cron ativo. sar-scheduler.timer habilitado e active (waiting); logs registram Agendamentos sincronizados.
- journalctl do kernel nos 15 minutos anteriores não mostrou registros correspondentes a DPT=587, DPT=465, DROP ou REJECT. Ausência de logs não prova ausência de filtro.
- tracepath UDP foi interrompido após 12 segundos sem saída útil; não identifica onde ocorre o bloqueio TCP.

## Interpretação

O timeout IPv4 na porta 587 ocorre ao estabelecer TCP, antes de receber o banner SMTP, negociar STARTTLS ou autenticar. A porta 465 também não respondeu. HTTPS funcionou em quatro endereços de Google/RNP nesta rodada, indicando que a VM possui conectividade externa IPv4 para esses destinos.

Os resultados são compatíveis com filtragem de saída SMTP ou um problema de rota específico para o destino/serviço. Não confirmam o equipamento nem a regra responsável. O erro IPv6 Network is unreachable explica o erro final de algumas chamadas que tentam ambas as famílias; IPv4 também falhou separadamente por timeout.

Nenhuma senha foi lida neste teste. Autenticação Gmail e STARTTLS não puderam ser testados porque TCP 587 não conectou. Zero e-mails enviados.
